## Задача

Сгенерировать документацию экрана на русском языке для Confluence по Figma-ссылке. Не спрашивать подтверждения — сразу генерировать.

## Шаги

1. Извлечь `fileKey` и `nodeId` из каждого URL:
   - Формат: `figma.com/design/:fileKey/...?node-id=:int1-:int2`
   - `nodeId` = `int1:int2` (заменить `-` на `:`)
2. Вызвать `mcp__figma__get_design_context` для каждого узла (параллельно, если ссылок несколько)
3. Заполнить шаблон ниже

## Шаблон документации

```
# [Название экрана]

## Экран содержит

**[Название UI элемента]** — [короткое описание: что содержит и/или что происходит по клику]
[Состояния / варианты / логика отображения — только если есть, обычным текстом]

## [Название крупного блока/секции] (H2 — только если есть именованный блок с несколькими элементами)

**[Название UI элемента]** — [описание]

---

## Нижняя навигация (добавлять только если есть)

**Основная кнопка** — «[текст]». По клику — [действие]
**Дополнительная кнопка** — «[текст]». По клику — [действие]

---

## Алерты / Модальные окна (добавлять только если есть)

**[Название алерта]**
- **Триггер:** [что вызывает]
- **Заголовок:** «[текст]»
- **Основная кнопка:** «[текст]» — [результат]
- **Вторичная кнопка:** «[текст]» — [результат]

---

## Альтернативный вариант: [название] (добавлять только если есть явный альтернативный сценарий с другим набором компонентов)

**Условие показа:** [когда показывается]

| Компонент | Основной вариант | Альтернативный вариант |
|-----------|-----------------|------------------------|
| [компонент] | [описание] | [описание] |

---

## Логика работы

[Откуда открывается экран, условия отображения элементов, навигация после действий пользователя]

---

## Google Analytics

---

## Тексты и переводы

| Элемент | Русский язык | Кыргызский язык |
|---------|-------------|-----------------|
| [название элемента] | [текст] | |
```

## Порядок секций (строго соблюдать)

1. Экран содержит
2. Крупные именованные блоки/секции — если есть
3. Нижняя навигация — если есть
4. Алерты / Модальные окна — если есть
5. Альтернативный вариант — если есть
6. Логика работы
7. Google Analytics — всегда, всегда пустая
8. Тексты и переводы — всегда

## Форматирование для Confluence

- Заголовки секций и крупные UI блоки — `##` (Заголовок 2)
- Названия отдельных UI элементов с описанием — `**bold**` (Абзац Bold)
- Описательный текст — обычный текст (Абзац default)

## Правила содержания

- Язык: **русский**
- Описывать только один экран — полный флоу не описывать
- **НЕ писать** метаданные (Фича/Флоу, Дизайнер, Дата, Figma, Статус)
- **НЕ писать** поля «Тип:» и «Контент:»
- Использовать названия из дизайн-системы (например: «стейка-разделитель», не «секция с заголовком»)
- Пустое состояние — **не** альтернативный вариант, описывать внутри компонента
- `Альтернативный вариант` — только если есть явный альтернативный сценарий с другим набором компонентов
- `Google Analytics` — всегда присутствует, всегда пустая
- `Тексты и переводы` — все текстовые строки экрана, третья колонка пустая

## Схема экрана (draw.io)

Помимо документации можно отрисовать схему экрана в виде диаграммы draw.io.

1. Сгенерировать файл `name.drawio` (XML формата mxGraphModel / draw.io) со схемой экрана — структура блоков, элементов и связей.
2. Пользователь импортирует этот файл в Confluence: в месте схемы вставляет макрос **draw.io** и связку с **Draw.IO**, затем импортирует загруженный `name.drawio`.

Файл `.drawio` отдавать как отдельный артефакт рядом с текстовой документацией.
